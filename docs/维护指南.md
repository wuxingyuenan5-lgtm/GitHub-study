# 仓库维护指南

## 如何新增一个项目

### 方式一：只加到元数据（推荐）

如果只是想让项目出现在索引中，编辑 `metadata/projects.yaml`：

```yaml
- id: X-XX                    # 在对应分类内递增
  category: X
  category_name: 分类名称
  name: 项目名称
  repo: owner/repo
  url: https://github.com/owner/repo
  stars: "~1k"                # 近似值或"未显示"
  license: MIT                # 未标注则写"未标注"
  tags: [推荐, MCP]           # 可选：热门、冷门、推荐、冠军、比赛、MCP、实盘、学习
  summary: 一句话说明
```

然后运行：

```bash
python scripts/generate_index.py
```

### 方式二：新增到分类 README

如果希望有详细的优缺点分析，还需要编辑对应分类的 `README.md`：

1. 在分类 README 末尾追加项目条目
2. 保持格式与其他条目一致
3. 更新分类 README 末尾的总结表

### 方式三：新增分类

如果现有 20 个分类都无法容纳：

1. 在 `metadata/projects.yaml` 中使用新分类字母（如 U）
2. 创建新目录 `U-分类名称/`
3. 在该目录下创建 `README.md`
4. 更新根目录 `README.md` 的目录表
5. 运行 `python scripts/generate_index.py`

## 更新项目 Stars

目前 Stars 是手动维护的。未来可添加 `scripts/update_stars.py` 通过 GitHub API 自动更新。

在自动化之前，建议每季度手动检查一次热门项目。

---

## 不做什么

- **不要**克隆项目源码到本仓库
- **不要**上传项目的 `.git` 目录
- **不要**上传模型文件（`.pth`、`.ckpt`、`.bin` 等）
- **不要**上传大数据文件（`.csv.gz`、`.parquet`、`.h5` 等）
- **不要**把许可证未标注的项目标注为"可商用"

这些规则已写入 `.gitignore`。

## 命名规范

- 分类目录：`大写字母-中文名称`
- 项目 ID：`<分类字母>-<两位序号>`
- 文件名：使用中文，语义清晰
- 链接：使用 HTTPS，优先使用 GitHub 原始仓库地址

---

## 标签使用建议

| 标签 | 含义 |
|------|------|
| 热门 | Stars > 5k 或社区活跃 |
| 冷门 | Stars < 500 或小众项目 |
| 推荐 | 虽然冷门但价值高，值得优先关注 |
| 冠军 | 比赛第一名方案 |
| 比赛 | 比赛方案或论文复现代码 |
| MCP | 支持 Model Context Protocol，可嵌入 AI Agent |
| 实盘 | 可直接或接近实盘交易 |
| 学习 | 教程、书籍、资源清单 |
